零知识本地知识库软件 V1.0
用户手册
（依据 GB/T 8567-2006 编写）

────────────────────────────────────────────────────────────────

1  引言
────────────────────────────────────────────────────────────────

1.1  编写目的

本手册面向《零知识本地知识库软件 V1.0》的最终用户，说明软件的安装、
卸载、日常操作（创建/解锁、文档编辑、检索、备份、同步、修改主密码）、
运行参数配置以及常见故障的处理方法，帮助用户安全、完整地使用本软件
管理自己的私有知识数据。

1.2  软件简介

零知识本地知识库软件是一款“零知识、本地优先”的私有知识管理工具：
  · 所有文档在写入本地存储前，先在用户端完成 AES-256-GCM 加密，
    存储介质与服务器仅保存密文，任何第三方都无法读取文档内容；
  · 提供文档创建/编辑/删除、全文检索、离线备份（.kb）与离线同步
    （.kbsync）、Markdown 编辑与实时预览、修改主密码（重设密钥）等功能；
  · 无需联网即可完整使用（核心功能 100% 离线可用）。

1.3  运行环境

  浏览器模式（推荐）：
    Windows 10/11、macOS 或主流 Linux 桌面发行版；
    Chrome / Edge / Firefox / Safari（近两个主要版本），需支持 WebCrypto。
  命令行/无头模式：
    Node.js ≥ 22（内置 node:sqlite 与 node:test，无需任何 npm 依赖）。

1.4  术语

  · 主密码：创建知识库时设置的密码，是解锁全部数据的唯一钥匙。
    丢失主密码将无法找回数据，请务必妥善保存。
  · 工作区：一套独立加密空间；不同工作区之间密钥彼此隔离。
  · .kb 备份文件：仅含密文的便携备份，用于迁移或恢复。
  · .kbsync 同步磁带：仅含密文的离线同步文件，用于两台机器间收敛数据。

2  安装与卸载
────────────────────────────────────────────────────────────────

2.1  浏览器模式安装

本软件为纯静态 Web 应用，安装即“部署静态文件”，无需编译：
  步骤 1：将软件包（src、public、server 目录）完整复制到目标机器；
  步骤 2：在命令行进入软件根目录，执行：
              node server/demo.mjs
  步骤 3：用浏览器打开提示地址（默认 http://localhost:4242）即可进入
          创建/解锁界面。
  说明：本软件为纯静态页面，也可将整个软件包根目录（含 public/ 与
  src/，页面经 ES 模块 import 引用）部署到任意静态站点服务器
  （Nginx、Apache、Web 服务器等），效果一致；页面自包含全部加密
  与解密逻辑，服务端仅负责文件传输，不存储任何业务数据。

2.2  命令行/无头模式安装

  步骤 1：安装 Node.js ≥ 22（含内置 sqlite 支持），无需安装第三方包；
  步骤 2：复制软件包到目标目录，在根目录执行：
              npm test              运行全部 84 项自动化测试
  本软件无第三方运行时依赖，“安装”即完成；数据库文件按需在工作区
  首次创建时自动生成。

2.3  最低配置要求

  · CPU：1 GHz 及以上；
  · 内存：512 MB 及以上（推荐 2 GB）；
  · 磁盘：按知识库大小，建议预留 1 GB 以上空闲空间；
  · 浏览器：支持 WebCrypto 的现代浏览器。

2.4  卸载

  浏览器模式：(1) 删除部署目录；(2) 如需彻底清除本地数据，在浏览器
  开发者工具的“应用程序 → IndexedDB”中删除本软件对应的数据库
  （或以浏览器“清除站点数据”完成）。
  命令行模式：删除软件目录及其下的数据库文件即可（此为彻底移除，
  请在删除前确认已导出 .kb 备份）。

3  操作说明
────────────────────────────────────────────────────────────────

3.1  创建知识库（首次使用）

  1) 打开页面，在“创建知识库”卡片中：
     · 填写工作区名称（如“我的私人笔记”，仅用于密钥空间隔离，不落明文）；
     · 设置主密码（建议 ≥ 12 位，包含大小写字母、数字与符号），
       并再次确认；
  2) 点击“创建知识库”；
  3) 系统随即生成加密工作区并自动进入解锁态，即可开始记笔记。

  安全提示：主密码是解密全部数据的唯一凭据；系统不会也不能提供
  找回功能，请使用可靠的方式保管。

3.2  解锁（再次访问）

  每次打开页面（或闲置一段时间自动锁定后），需用主密码解锁：
  1) 输入主密码；
  2) 点击“解锁”；
  3) 解锁成功后自动重建全文索引，显示全部文档列表。
  · 页面在指定时间内没有操作（移动鼠标、按键、滚动等）会自动锁定，
    丢弃会话主密码并清空内存明文；自动锁定前会自动保存未保存的编辑，
    不会丢失内容。
  · 密码错误将被校验器直接拒绝，不会产生任何可读数据，也不会破坏
    现有数据。

3.3  文档管理

  新建文档：
  1) 点击“新建文档”；
  2) 输入标题与正文（支持 Markdown 语法）；
  3) 点击“保存”（或按 Ctrl/Cmd + S）。
  编辑文档：在文档列表点击标题打开，修改后保存；未保存的修改在切换
  文档或离开页面时会收到提醒，避免丢失。
  删除文档：在文档列表对目标文档执行删除并确认；删除会记录同步墓碑，
  之后即使从旧备份/旧同步磁带也无法“复活”该文档。
  文档持久化：保存即在本机完成端到端加密并写入本地存储；关闭页面、
  重启浏览器后再次解锁即可看到全部文档。

3.4  全文检索

  · 在顶部检索框输入关键词；
  · 系统对标题、正文、代码、引用与表格单元格进行全文匹配，实时
    列出命中文档；
  · 检索基于内存中的 FTS5 索引，不产生任何磁盘明文。
  技巧：关键词可连续用空格分隔、对表格内文字进行检索；检索索引在
  每次解锁时从解密后的文档自动重建。

3.5  Markdown 编辑与预览

  · 编辑器支持：标题（# 一至六级）、段落、引用（>）、代码块
    （``` 或 ~~~）、无序/有序列表、管道表格（| 表头 | 表头 |）；
  · 点击“预览”按钮可实时查看渲染结果；再次点击切回编辑；
  · 表格自动作为一个整体块保存，调度与 Markdown 文本可无损互转；
  · 预览采用内置安全渲染器：先转义再渲染，自动屏蔽 javascript:、
    data: 等危险链接，恶意文档内容不会执行脚本。

3.6  导出备份（.kb）

  1) 在解锁状态下点击“导出 .kb”；
  2) 浏览器下载仅含密文的备份文件（文件名含导出时间）；
  3) 妥善保管该文件（请同样牢记主密码）。

3.7  导入备份（.kb）

  1) 在新机器（或清空后的环境）解锁同一工作区，点击“导入 .kb”；
  2) 选择备份文件，系统校验格式与工作区一致性后恢复全部文档；
  3) 已存在的相同文档不会被重复写入（幂等导入）。
  注意：导入只接受与当前工作区匹配的备份；不同工作区的备份会被拒绝，
  以免造成数据错乱。

3.8  离线同步（.kbsync）

  场景：两台机器 A、B 共享同一工作区（同一主密码与工作区名），希望
  双向收敛文档（包括删除）。
  1) 机器 A 解锁后点击“同步引出”，下载 .kbsync 磁带文件；
  2) 将该文件用任意方式（U 盘、即时通讯、自建网盘等）带到机器 B；
  3) 机器 B 解锁后点击“同步引入”，选择该文件；
  4) 待机器 B 上产生新的修改后，同样引出 .kbsync 给机器 A 引入；
  5) 双方互相交换一次后，两台机器的文档集合与各文档最新版本一致。
  同步规则（LWW）：同一文档以更新时间最新的一版为准；删除以墓碑
  形式传播；重复应用同一磁带不会产生重复或破坏性副作用；不同工作区
  的磁带会被拒绝。

3.9  修改主密码（重设密钥）

  1) 确保当前处于解锁状态，展开“修改主密码”卡片；
  2) 输入当前主密码、新主密码并再次输入确认；
  3) 点击“修改主密码”；
  4) 系统将全部文档的密钥在新密码下重新封装并重建校验器；完成后
     旧密码立即失效，全部文档完好无损。
  提示：若担心主密码强度，请包含大小写字母、数字与符号，长度越长
  越安全。

4  配置与参数
────────────────────────────────────────────────────────────────

4.1  可配置项一览

  项目              默认值                  说明
  服务端口          4242                    server/demo.mjs 监听端口，
                                            可用环境变量 PORT 覆盖
  自动锁定        闲置 5 分钟                解锁状态下连续无操作自动
                                            锁定并丢弃会话密钥
                                            （见 3.2 节）
  工作区名称        由用户创建时指定          参与 HKDF 密钥命名空间派生
  主密码            由用户设置               ≥ 8 字符，建议 ≥ 12 字符
  PBKDF2 迭代次数   310,000                 密钥派生强度，固定内置
  加密算法          AES-256-GCM（12B IV）   文档密文与 DEK 封装算法
  密钥派生          PBKDF2-SHA256 + HKDF-SHA256
  全文索引          FTS5（内存，porter 分词）
  备份格式          .kb（JSON，仅密文）
  同步格式          .kbsync（文本，仅密文）

4.2  密码与密钥参数

  · 每个文档使用独立随机 DEK；DEK 由工作区密钥 AES-256-GCM 封装后
    与文档密文一同保存；
  · 工作区密钥派生链：主密码─PBKDF2(310,000)→解锁密钥─HKDF→工作区密钥；
    工作区密钥永不以任何形式写盘；
  · 修改主密码后，全部 DEK 自动在新密钥下重新封装（重设密钥）。

4.3  存储位置

  浏览器模式：数据保存在浏览器 IndexedDB 中（数据库名如 local-kb）；
  命令行模式：数据保存在工作目录下的 SQLite 数据库文件中；
  备份/同步文件：由用户自行保存（.kb / .kbsync）。

5  故障处理与 FAQ
────────────────────────────────────────────────────────────────

5.1  常见故障与处理方法

  故障 1：解锁提示“密码错误”
  原因：主密码输入有误，或该密码并非此知识库的密码。
  处理：核对大小写与输入法；确认其属于当前工作区；重复失败不会
  损害数据。
  故障 2：解锁成功后文档列表为空
  处理：确认解锁的是正确的知识库/工作区；若使用浏览器，注意是否
  切换了浏览器或清理过站点数据（需以 .kb 备份导入恢复）。
  故障 3：导入 .kb 被拒绝，提示“不同工作区”
  原因：备份文件来自与当前工作区不匹配（名称或盐值不同）的知识库。
  处理：在目标位置（全新环境）以原工作区名与主密码创建并解锁后导入；
  或确认文件名确实为需要的备份。
  故障 4：检索不到本应存在的内容
  处理：检查检索词是否包含超出分词规则的符号；检索索引每次解锁重建，
  请先解锁再到检索框查询；确认文档标题/正文确实包含关键词（表格
  单元格同样可检索）。
  故障 5：猜想文档“丢失”
  处理：先确认当前是否处于解锁态（锁定界面不显示任何文档）；再检查
  是否误删（删除有二次确认）；若在另一台机器上，需通过 .kbsync 或
  .kb 恢复。
  故障 6：浏览器页面无法打开
  处理：确认已执行 node server/demo.mjs 且端口未被占用；默认端口
  4242，可设置环境变量 PORT=其他端口后重启；确认浏览器支持 WebCrypto。
  故障 7：预览中表格显示异常
  处理：确认表格为管道语法（| 表头 | --- | 第1行 |）；单元格内的
  竖线请用反斜杠转义（\|）；表格不会被拆散成普通段落。

5.2  安全使用建议

  1) 主密码请选择高强度且独一无二的密码，并使用密码管理器保存；
  2) 定期导出 .kb 备份，并妥善保管（备份文件内无明文，丢失密码
     则备份亦不可用）；
  3) 在不可信设备上使用后，及时“锁定/关闭页面”并清除浏览器缓存；
  4) .kbsync 磁带仅含密文，传输渠道被截获也不会泄露内容，但仍建议
     在可信渠道传递。

5.3  FAQ（常见问题）

  Q1：忘记主密码怎么办？
  A：按设计无法找回。主密码为唯一解密凭据，系统不保存任何可恢复
     信息。请务必妥善保管。
  Q2：文件存储到服务器了吗？服务器能看到内容吗？
  A：演示服务器仅提供静态文件传输服务，不保存业务数据。即使服务端
     或存储介质被他人获取，因其上仅有密文，也无法读取文档内容。
  Q3：软件需要联网才能使用吗？
  A：不需要。创建、编辑、检索、备份、修改主密码全部离线可用；
     同步采用离线文件（.kbsync）或自建渠道传递。
  Q4：能否在浏览器之外使用？
  A：可以。命令行（Node.js ≥ 22）模式提供同样的核心能力，并可通过
     npm test 运行 84 项自动化回归测试。
  Q5：同两台机器如何保持同步？
  A：见 3.8 节：分别在两台机器“同步引出 / 同步引入” .kbsync 文件
     各一次，即可双向收敛（含删除语义）。
  Q6：修改主密码后，文档会丢失吗？
  A：不会。全部文档在新密码下重新封装（Re-Key），文档内容不变；
     旧密码即刻失效且无法再解开任何数据，请务必记住新密码。
  Q7：数据在内存中是明文吗？有风险吗？
  A：解锁状态下文档明文仅存在于本机内存与页签中，用于编辑与检索；
     关闭页面或锁定后即释放。这是“零知识”设计的必然折衷，请在
     使用公共电脑时保持警惕。
  Q8：源代码的安全基线如何保证？
  A：工程内置 84 项自动化测试，覆盖“磁盘/IndexedDB 无明文”、
     “错误密码拒绝访问”、“检索畸形查询容错”与浏览器端 XSS
     防护等安全断言，作为持续回归基线。
