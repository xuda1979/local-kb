1  引言
────────────────────────────────────────────────────────────────

1.1  编写目的

本说明书阐述《零知识本地知识库软件 V1.0》的总体结构与详细设计，
供软件管理人员、开发人员和维护人员了解本软件的体系结构、模块划分、
关键算法与数据结构，作为软件著作权登记、技术评审与后续维护的依据。

1.2  项目背景

知识库类软件（Notion、语雀等）通常将用户文档以明文形式存储于服务端。
对于注重隐私的个人与小型团队，文档内容存在被服务端读取、泄露与审查的
风险。本软件面向“零知识、本地优先”的设计目标，在写出磁盘/数据库
之前即在用户端完成端到端加密，存储介质与服务器仅保存密文，从根源上
消除明文泄露面；同时提供全文检索、离线备份与离线同步等完整功能，
形成一套可离线运行的私有知识管理解决方案。

1.3  术语与缩略语

  DEK           Data Encryption Key，数据加密密钥（AES-256-GCM，每文档随机）
  PBKDF2        Password-Based Key Derivation Function 2（密钥派生）
  HKDF          HMAC-based Key Derivation Function（密钥派生/扩展）
  AEAD          Authenticated Encryption with Associated Data（带认证的加密）
  IV            Initialization Vector，初始化向量（12 字节随机数）
  FTS5          SQLite 全文检索扩展（第五代全文搜索）
  LWW           Last-Writer-Wins，最后写入胜出的冲突收敛规则
  tombstone     墓碑，用于传播删除操作的同步记录
  .kb           备份文件格式（JSON 序列化，仅含密文）
  .kbsync       离线同步磁带文件格式（仅含密文）

1.5  软件概述

软件的总体任务是提供一套零知识加密的知识管理环境，核心目标为：
  a) 所有文档内容在用户端加密后才落地存储；
  b) 提供文档增、删、改、查与全文检索；
  c) 提供备份导入/导出与离线同步；
  d) 提供 Markdown 编辑、预览与防 XSS 安全渲染。

1.6  运行环境

  · 开发语言：JavaScript（ES2023）
  · 运行平台：Node.js ≥ 22（headless 模式，内置 node:sqlite）；
              现代浏览器（Chrome/Edge/Firefox/Safari，WebCrypto-AES-GCM）
  · 存储介质：SQLite3（CLI 端）；IndexedDB（浏览器端）
  · 配置文件：无（工作区参数存于数据库，主密码由用户记忆）

2  总体设计
────────────────────────────────────────────────────────────────

2.1  总体结构

本软件自底向上划分为三层：
  · 存储适配层（Standalone / Browser）：统一封装存储介质访问，向业务层
    提供一致的接口（保存参数、文档增删改查、墓碑、FTS 维护等）；
  · 加密与业务层：密钥派生、文档 DEK 封装、工作区创建/解锁、
    文档存储、全文检索、备份、同步、Re-Key；
  · 表示层（Web 客户端 + Markdown 渲染器 + 演示服务器）：用户交互。

模块清单（src/ 目录）：

  crypto.js       密码学原语：PBKDF2/HKDF/AES-256-GCM/base64url、随机数
  workspace.js    工作区创建/加锁/解锁（主密码校验门）
  store.js        文档存储：DEK 封装/解封、创建/编辑/删除/列表/检索
  db.js           SQLite 后端（node:sqlite）+ 内存 FTS5 索引
  bak.js          .kb 备份的序列化/反序列化/导出/导入
  rekey.js        修改主密码：全部 DEK 重新封装并重建校验器
  factory.js      高层装配与 Markdown↔块模型转换
  docmodel.js     文档块模型（文档标题/段落/章节标题/代码/引用/表格）
  sync.js         密文同步平面：localTape/mergeTape/applyTape
  syncfile.js     .kbsync 磁带文件构建/解析/应用与工作区鉴权
  util.js         通用工具（UUID、时间戳等）
  index.js        对外导出

web 客户端（public/）：
  index.html      解锁/创建/主界面（编辑器、预览、文档列表、检索、导入导出、同步、改密）
  main.js         视图状态与业务交互
  markdown.js     Markdown 渲染器（escape-first 防 XSS）
  idb.js          IndexedDB 存储适配

server/：
  demo.mjs        静态演示服务器（仅提供文件与 /api/health）

2.2  加密体系总体设计

密钥分层（三层）：

  主密码 masterPassword
    └─ PBKDF2-SHA256（310,000 迭代，随机 16 字节盐） → 解锁密钥 unlockKey
         └─ HKDF-SHA256（info: "local-kb/ws:" + 工作区名）→ 工作区密钥 workspaceKey
              └─ AES-256-GCM 封装 → 每文档数据密钥 DEK
                   └─ AES-256-GCM 加密 → 文档 JSON → 密文

设计要点：
  a) 工作区密钥只由主密码派生，永不以任何形式落盘；
  b) 每个文档生成独立随机 32 字节 DEK，用工作区密钥封装后与密文同存
     （dekIv/dekData）；单个文档密钥泄露不影响其余文档；
  c) 文档密文由该文档 DEK 加密，IV 均为 12 字节随机数，防重放/重排；
  d) 工作区记录校验器 verifier：用工作区密钥加密的固定常量密文，
     解锁时解密比对，错误密码立即整体失败（AEAD 认证标签即失效）。

2.3  数据结构设计

数据库表（SQLite / IndexedDB 同构）：

  workspace 表（单行）
    name, version, salt, iterations,
    verifier {iv, data}      — 解锁门的密文校验器
  docs 表（每文档一行）
    id            UUID
    dekIv, dekData  封装的 DEK
    iv, data        文档密文（AES-256-GCM，DEK）
    created_at, updated_at
  meta 表
    tombstone:<docId>       — 删除墓碑（记录删除时刻 updatedAt）

文档块模型（docmodel.js）：

  文档 = {title, blocks}
  block = {type∈{title,paragraph,heading,code,quote,table}, text}
  serializeDoc/deserializeDoc 负责与 JSON 互转。

2.4  系统工作流程

  a) 创建工作区：输入主密码 → 随机盐 → PBKDF2 → HKDF 派生工作区密钥 →
     写入参数与校验器 → 建立 DocStore；
  b) 解锁：读参数 → PBKDF2/HKDF 重新派生 → 解校验器验证 → 遍历文档
     解密并重建内存 FTS 索引（reindexAll）；
  c) 保存文档：文档 JSON → 随机 DEK 加密 → 工作区密钥封装 DEK →
     adapter.putDoc；同时更新内存 FTS 索引；
  d) 删除文档：写入 tombstone → 从 FTS 移除；
  e) 检索：FTS5 对内存索引查询，返回命中文档 id；
  f) 备份/导入：.kb JSON（版本+参数+行密文+DEK）序列化/反序列化；
  g) 同步：localTape 生成密文磁带 → .kbsync 文件传输 → 对端
     parseTape/applyTape 按 LWW 收敛；
  h) 改密：解锁成功后，遍历每个文档用旧工作区密钥解封 DEK → 用新工作区
     密钥重新封装 → 最后重建校验器并保存参数（原子收尾，旧密码即失效）。

  工程源程序总行数（去除注释与空行）：2973 行（含注释与空行约 3825 行）。

2.5  模块划分与接口关系

  表示层 ──► factory.js（createKb/openKb）──► store.js（DocStore）
  DocStore ──► workspace.js（派生密钥/校验）──► crypto.js（原语）
  DocStore ──► adapter（db.js / idb.js）──► 存储介质
  store.js  ◄──► sync.js / syncfile.js（同步磁带）
  store.js  ◄──► bak.js（备份）
  factory.js ──► docmodel.js（块模型）

3  详细设计
────────────────────────────────────────────────────────────────

3.1  密码学模块（crypto.js）详细设计

模块函数：
  · PBKDF2_ITERATIONS = 310000
  · getCrypto()：返回 globalThis.crypto（Node 与浏览器双端）
  · randomBytes(n)：密码学安全随机数（getRandomValues）
  · toBase64/fromBase64：URL 安全 base64（-/_，去除填充）编解码
  · deriveUnlockKey(password, saltB64, iterations, hash)：PBKDF2-SHA256
    派生 AES-GCM 256 位加解密密钥（可 wrapKey/unwrapKey 使用）
  · deriveKeyBytes(...)：返回原始密钥字节，供 HKDF 输入
  · hkdfExpand(keyBytes, info) / deriveWorkspaceKey(password, salt, wsName)：
    HKDF-SHA256 展开，info = "local-kb/ws:" + wsName，
    输出确定性的工作区密钥
  · importAesGcm(keyBytes)：导入为可用的 CryptoKey
  · encrypt(key, plaintext)/decrypt(key, iv, ct)：AES-256-GCM，
    IV 12 字节，输出 {iv, data}（base64url），解密失败抛错
  · utf8e/utf8d：TextEncoder/TextDecoder 封装
  · isNode：平台探测

设计说明：
  a) 采用 WebCrypto SubtleCrypto 而非自行实现的算法，安全性与平台一致；
  b) 盐、迭代次数存于 workspace 表（公开非敏感），主密码不在任何介质
     留存；暴力破解防护由 310,000 次 PBKDF2 迭代保证；
  c) 所有加解密封装为纯函数，业务层不接触原始密钥字节。

3.2  工作区模块（workspace.js）详细设计

  · createWorkspace(masterPassword, wsName)：
    随机 16 字节盐 → deriveWorkspaceKey → 生成 verifier（对固定常量
    "local-kb::unlock-verifier::v1" 加密）→ 返回 {name, version=1,
    salt, iterations, verifier, workspaceKey}
  · unlockWorkspace(params, masterPassword)：
    由参数重新派生工作区密钥 → 解 verifier 比对 → 成功返回 workspaceKey，
    失败返回 {ok:false, error:'wrong-password'}

3.3  SQLite 存储后端（db.js）详细设计

  · SQLiteBackend 实现适配器接口：
      workspace.rows   getParams/saveParams
      meta             getMeta/setMeta；deleteMeta
      docs             listDocs/getDoc(含墓碑判定)/putDoc(upsert)/
                       deleteDoc/markDeleted（写墓碑）
      fts              ftsPut/ftsDelete/ftsSearch（内存 FTS5）
      tombstones       listTombstones
  · 内存 FTS5：docs_fts 虚拟表（content 列 tokenize='porter'），
    _rowidFor/docIdForRow 维护单调 rowid↔docId 映射，杜绝 rowid
    重用导致索引串号；ftsSearch 对恶意/畸形查询 try/catch 返回空集
  · markDeleted 记录 meta.tombstone:<id> = updatedAtISO

3.4  文档存储（store.js）详细设计

  DocStore（构造参数：adapter, workspaceKeyHandle）
  · create(id, title, blocks)：随机 DEK → wrapDEK(工作区密钥, DEK) →
    加密文档 JSON → computed updatedAt → adapter.putDoc → FTS 更新
  · edit(id, title, blocks)：重取文档 → 原 DEK 解封 → 重新加密 → 更新
  · delete(id)：adapter.deleteDoc + 记录墓碑 + FTS 移除
  · get(id)/list()：get 解密单文档返回 {id,title,blocks,createdAt,
    updatedAt}（无则 null）；list 遍历全部密文行逐一解密返回完整文档
    列表（同构，无分页；明文仅存内存，不落盘）
  · tryDecrypt(docRow)：解封 DEK → 解文档密文 → 解析 JSON 返回块
  · plaintextForIndex(doc)：拼接标题+各块文本（含表格单元格），供 FTS
  · search(query)：(await adapter.ftsSearch(query)).map(docIdForRow)
  · reindexAll()：解锁时从解密文档重建索引（明文仅在内存）

3.5  备份模块（bak.js）详细设计

  · exportKB(params, docRows) → {format:'local-kb', version, params, docs}
  · serializeKB → JSON 字符串 / parseKB 返回 {params, docs}
  · deserializeKB → 对象
  · importKB(adapter, parsed)：校验工作区盐值一致（盐不同则工作区密钥
    必然不同，拒绝导入以防孤儿文档），幂等（已存在同步 DEK 的文档
    跳过），批量写入

3.6  Re-Key 模块（rekey.js）详细设计

  changeMasterPassword(adapter, current, newPassword)：
  1) 用 current 解锁，失败则返回错误且零副作用（先验后改）；
  2) 用 new 派生新工作区密钥；
  3) 遍历所有文档：解封 DEK → 用新工作区密钥重新封装；
  4) 重算 verifier；最后才 saveParams（原子切换，旧密码即刻失效）；
  5) 全程无明文接触磁盘；重复改密稳定。

3.7  同步平面（sync.js / syncfile.js）详细设计

  · mergeTape(a, b)：按 docId 合并两条磁带，LWW 对 (updatedAt, id)
    取优，输出确定序；无效条目忽略；
  · applyTape(tape, adapter)：逐条应用；已存在同版本跳过（幂等）；
    本地更新的则不入侵；deleted:true 条目：比本地新才删除，本地不存在
    时采纳墓碑以阻断旧磁带复活；返回 {applied, skipped}
  · localTape(adapter)：每个存活文档一条密文条目 + 每条墓碑一条
    deleted:true 条目；若文档已重建则丢弃过期墓碑（防争用复活）
  · syncfile.js：buildTape → serializeTape(.kbsync 文本) →
    parseTape（校验格式/版本/工作区标识）→ assertSameWorkspace（工作区
    盐鉴权，拒绝跨工作区磁带）→ applyTapeFile

3.8  Markdown 编辑与渲染（public/markdown.js + factory.js）详细设计

  · textToBlocks(text)：按行扫描；连续管道行（以 | 开头或含 |）合并为
    table 块（保留原文，含转义管道 \|）；# 开头为 heading、```/~~~ 为
    code、> 为 quote、其余为 paragraph；heading/quote 行保留原始标记
    （如 ###、> 的多级）逐字存储，段落间遇空行自动切块
  · blocksToMarkdown(blocks)：heading/quote/code/table 按块内原文逐字
    回显（旧文档缺失标记时按 # / > 兜底补全）；段落原样输出；块间
    空行连接
  · renderMarkdown(md)：escapeHtml 先行转义，再按行/正则渲染：
    标题、水平线、围栏代码块、块引用、无序/有序列表、管道表格
    （safeHref 仅放行 http(s):/mailto:/#// 相对链接，javascript: 与
    data: 降级为纯文本），实现 escape-first 的 XSS 防御

3.9  浏览器存储适配（public/idb.js）与视图（public/main.js）

  · IndexedDBBackend：实现与 SQLiteBackend 相同接口；workspace/docs/
    meta 三个 object store；FTS 为内存 Map 结构，与 SQLite 的
    ftsPut/ftsDelete/ftsSearch 语义一致
  · main.js：状态机（锁定/解锁）管理视图切换；markDirty/clearDirty
    未保存提醒；Ctrl/Cmd+S 保存；导出/导入 .kb、同步引出/引入 .kbsync、
    修改主密码等交互均通过 store 层完成，全程密文流

3.10 可靠性、安全与容错设计

  a) 错误密码：verifier 校验失败立即中止，不产生任何写操作；
  b) 篡改检测：解密任意层失败均由 AEAD 认证标签确诊为篡改/错密；
  c) 检索容错：畸形 FTS 查询返回空集不抛出；
  d) 同步容错：磁带重复应用为无操作；跨工作区磁带拒绝；
     墓碑与最新写入的时序竞争通过 LWW + 版本匹配规则消除；
  e) 备份导入幂等性：重复导入不产生重复文档；
  f) 前端 XSS：escape-first + 安全 URL 白名单双重防护。
